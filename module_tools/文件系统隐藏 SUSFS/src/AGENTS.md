# SUSFS LKM 迁移约定

版本约定（2026-10-21）：每轮功能更新都必须推进 SUSFS 模块版本号，并同步递增安装包 versionCode。新增功能、行为调整和内核适配均属于功能更新。用户指定目标版本时采用指定值；未指定时默认递增末位版本号。同一轮更新中的修订和重复打包沿用该轮版本。同步更新 module/identity.h、module/package_standalone.py 和当前构建文档中的版本示例，并确保原生模块元数据、module.prop、构建清单及交付文件名一致；历史记录和旧产物保留原版本。

安装包命名约定（2026-10-24）：后续 SUSFS 模块安装包统一使用 `版本号-6.6-6.12-名称-其它.zip`，版本号放在文件名最前，随后为内核版本、模块名称和其它说明；例如 `0.3.6-6.6-6.12-文件系统隐藏SUSFS-上游修复-arm64.zip`。打包时显式传入符合此约定的 --out 路径，历史产物保留原名。此命名及文档调整本身不推进功能版本号。

以 UPSTREAM.json 固定的最新 main 为起点，保留上游历史。空规则、启动时机及各层初始化沿用上游；uname、cmdline/bootconfig、AVC、模块和符号隐藏沿用上游全局语义，不接入应用分组。

仅路径、属性、重定向、映射和挂载五类对象功能接入主体筛选及分组。完整 UID、共享 UID、黑白名单、系统应用事实、精确管理身份必须如实处理。策略核心能选择 profile 不等于对象表已实现分组隔离；能力未完成时在接口上拒绝，不能只改变显示。

设备拦截测试仅允许本项目自行编译并核实实际包名/UID/进程身份的 Probe App，以及专用靶场 App“Maple检测”。对象限自建夹具或允许 App 的靶场数据。不得使用其他应用进行拦截测试，不借用其 UID/PID、授权或业务数据，不以独立 native 探针冒用应用身份。root 权限不扩大测试范围。

主机单元测试、构建和模块控制诊断单列；构建或加载成功不代表设备规则效果通过。原始用户诊断、boot、凭据和设备备份不进入仓库。构建生成物写入 build/ 或仓库外。

首装默认配置约定（2026-10-22）：management/default_config.hpp 保存用户提供的初始规则和高级配置，默认开启不保留后台。只在 config.json 不存在时写入，沿用普通启动应用/包清单重试；已有空配置、已修改配置和损坏配置均不得用默认值覆盖。用户可编辑、删除默认规则及非固定作用组，保存后重启不得补回。配置准备须在服务就绪前完成，保证首个 WebUI 会话读到正确后台偏好；准备阶段不操作内核。

内容隐藏兼容约定（2026-10-24）：0.3.8 起复用基础 inode_permission 阻止匹配目录下的路径查找，A 本身的打开、chdir、access 保留。该模式不以 file_open、目录别名或新增 readlink/follow_link 钩子作为准入条件，目录枚举继续需要原 getdents 路径与真实目录 FD。不得假报枚举能力；明确保留创建受限和生效前内部目录引用的边界。默认配置及字段保持，作用组和精确 manager 选择器必须一致。

SCS兼容约定（2026-10-24）：函数入口资格须兼容编译器直接生成或加载器由PAC转换的标准SCS指令，不以具体内核小版本或转换来源作为硬前置。仅在内核未启用BTI且配置支持影子调用栈时接纳SCS-only入口。已有目录入口跳转保留，不改写、不强制放行；原链后过滤与0.3.10空批次续读继续保留。

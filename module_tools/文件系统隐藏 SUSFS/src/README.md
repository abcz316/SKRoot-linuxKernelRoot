# SUSFS 独立模块与 LKM

当前模块版本为 **0.3.11**，安装包 `versionCode` 为 **16**。每轮功能更新（含行为调整和内核适配）都必须推进版本号，并同步递增 `versionCode`；用户未指定目标版本时默认递增末位。同一轮修订和重复打包沿用该轮版本。原生模块元数据、安装包信息、构建清单、文件名及当前文档示例须一致，历史记录和旧产物保留原版本。执行约定见 [AGENTS.md](AGENTS.md)。

本地 LKM 以 upstream main `6753d9c189b058a5978eddd7d2093f95b5be68a2` 为基线，保留已验证的 readlink 缓冲和 Android 可见挂载根修复。当前发布形态是独立 SUSFS SKP 模块，固定模块 ID 为 `fa362333cf458e832cd032fda9a9f3c6`；PLUS 不再内嵌本 LKM 或管理服务。

2026-10-21 已选择同步上游至 638374f 中的 bootconfig 内存回收、uname 字段清零、挂载记录失效、旧全局挂载分批扫描及 HARDENED_USERCOPY 条件依赖修复；具体提交和适配记录见 UPSTREAM.json。bootconfig 更新采用串行发布与真实的 RCU Tasks 宽限期，缺少该同步接口时拒绝替换，不使用固定延时释放。uname 的最终返回值也会清零短字符串尾部，覆盖运行期间修改参数的情况。挂载记录读写共用锁以避免失效或复用槽位时读取不一致的键；旧全局扫描最多 16 轮、每轮 8 项，不改变分组挂载规则的处理方式。KernelSU 控制节点授权和 AVC 扩展没有随本批同步。

2026-10-24（0.3.6）选择同步探针重用时清理 disabled 标记、全隐藏目录的最小占位记录、能力声明及旧版 supercall 指令准入一致性、符号隐藏诊断修正。目录后过滤保留 d_off，native/compat 分别返回 24/12 字节的空记录并清除类型和尾部，不将这一占位当作 EOF；原 SKP actor 组合链保持。能力位只由对应层成功初始化建立，查询及旧版指令共用运行时判定；SKP 分组仍按原独立路由按需准备，辅助层失败不冒充 PATH 整体失败，可选层继续降级。此次不引入 create_gate、挂载扩容或新的 fatal 加载策略。

## 内核接口

管理层使用 `kernel/skp_sequential.h` 的逐项接口：按 path、kstat、map、redirect、mount 清理族规则，随后逐条添加。规则完全初始化后通过 RCU 列表公开；删除时使用必要锁、RCU 同步、对象引用和回调排空。内核不依赖 revision、摘要、WAL、job、owner lease 或永久 module pin。

上游的全局开关、加载降级和未声明行为保持原语义。分组、主体筛选和逐路径 scope 由每条规则携带。SKP Root 模式保留在凭据中的内核记账 UID 用于匹配包名和作用组，实际 UID 仍用于“排除 root”等权限类别判断；指定模式不会因当前 UID 变为 0 而漏过原应用。该处理不猜测父进程或进程名，无法保留原记账身份的外部 Root 服务不自动归属某个应用。当前本地构建覆盖 android15-6.6 和 android16-6.12，统一候选包按内核 release 自动选择对应 KO。6.6 的“按源权限替换只读内容”暂不开放，WebUI 置灰并说明；名称匹配使用独立于内容能力的共享 file_open 检查。其他 KMI 未声明完成 SKP 扩展适配。构建和主机验证不代表新增目标设备效果已通过。

目录隐藏保留原 getdents/SKP 处理链，在符合实时指令、BTF 和 CFI 资格的 6.6/6.12 原生标准 ext4/F2FS 目录上组合实际输出回调。隐藏项在写入应用缓冲区前被跳过，可见项继续执行原回调；使用现有的主体、管理身份与 `dev + inode + name` 判断，不读取 rootkey 或硬编码私有目录名。只有确认本次遍历完整组合并恢复时才跳过后置过滤。

未核验的内核、32 位 compat、FUSE、proc、其他目录操作表及本次观察不完整的路径，继续使用保留原链的后置过滤。尾部清理和同进程并发缓冲区观察限制仍存在；空批次通过原系统调用链继续读取，不再合成空名称占位项，不能把局部输出前过滤能力宣称为全路径保证。`/proc/susfs_skp_policy` 和管理服务 `/status` 的 `dirent` 对象报告可用文件系统、资格错误、完整覆盖、降级、回调恢复和漏探针计数。停止时先禁止新装配，等待在途请求完成，再撤销恢复钩子。

路径隐藏新增“仅隐藏文件夹内容”选项，新建目录规则默认开启：保留目录本身及进入目录的能力，隐藏其子目录和文件。关闭该选项继续隐藏目录本身；普通文件仍使用原来的文件隐藏。已有用户配置不自动改写，编辑时可单独切换；首次安装的内置默认目录均启用“仅隐藏文件夹内容”。新模式使用 schema 14 的 `{ "path": "/目录", "hide_contents": true }` 和独立添加命令；旧内核缺少 `path_contents_hide` 能力时明确拒绝，不回退为隐藏目录本身。

0.3.8 的内容隐藏复用基础 `inode_permission`：保留目录本身的 stat、打开、chdir 和权限查询，拒绝在匹配目录下继续搜索子路径。它不再要求共享 file_open、d_find_alias 或新增的 inode_readlink/inode_follow_link 钩子，重定向和只读内容替换仍按各自原条件工作。原 getdents 后过滤继续清理目录内容，actor 组合资格失败（例如 -116）不单独禁用该模式；必须存在目录 FD 查询、缓冲区和原生 getdents 入口，否则明确报告原因。

该兼容方案也会阻止受作用域应用在目录内创建、重命名或链接新对象。规则生效前已持有内部子目录 FD 或 cwd 的访问可能绕过目录入口检查；可用的原有路径检查仍参与，但不承诺这类旧引用、无路径打开、跨挂载根或 FUSE 代理后的完整隔离。既有 FD 不追溯关闭，目录外的同 inode 硬链接不因内容规则全局隐藏。

“名称匹配隐藏”支持填写完整名称，例如 `bin.mt.plus`，区分大小写，匹配任意位置的同名普通文件和目录；不使用子串、正则或通配展开。无需预先扫描或解析路径，后来出现或重命名为该名称的对象也会参与匹配。名称必须为 1–255 字节，不能含 `/`、NUL，也不能是 `.` 或 `..`。现有绝对路径规则继续使用原来的设备号/inode隔离。

名称规则在 PATH 家族内使用独立添加命令和 schema 12 的 `directory_names` 数组，仍携带所属作用组的主体选择器。旧配置保持兼容；缺少 `directory_name_hide` 能力的内核明确拒绝新规则。当前能力还依赖已安装的共享 `file_open` 入口，所交付的候选覆盖 android15-6.6 和 android16-6.12。新名称检查与只读内容替换共享同一入口，保留原 SELinux 结果，不额外争用静态调用槽。普通文件按实际访问的 dentry 名称判断，不按任意 inode alias 推断，从而不连带隐藏另一名称的硬链接。

名称匹配会作用于共享存储服务的底层读取，可能使豁免应用及模块文件页也看不到同名对象；这是该模式明确接受的行为，不承诺 FUSE 代理后的客户端豁免隔离。目录列表仅过滤明确报告 `DT_DIR`/`DT_REG` 的条目，不猜测 `DT_UNKNOWN`；符号链接及其他特殊文件不属于此模式。目录权限检查使用当前连接的目录 alias，挂载根或断开的 alias 不按名称推断。已有 FD 不追溯关闭；DAC/SELinux 在名称检查之前拒绝访问时保留原错误。本次只有主机回归、浏览器和构建验证，尚未完成设备效果验证。

分组重定向允许非 FUSE 来源指向 FUSE 目标（例如 `/proc/cpuinfo` 指向共享存储中的文件）；FUSE 来源仍拒绝，上游兼容规则仍保持两端 FUSE 拒绝。目标由应用自身身份正常打开，Android 存储权限和应用挂载视图继续生效；应先确认目标应用能够直接读取目标文件。此功能不使共享存储自动变为所有应用可读，也不增加隐藏目标的内部豁免。目标在不同应用挂载视图中若呈现不同设备号、inode 或挂载 ID，内容读取与反向路径/FD 信息修正须分别验证。当前没有宣称 Android 设备的 FUSE 效果已通过测试。

分组规则还可显式选择“按源权限替换只读内容”：支持 `/proc/cpuinfo`、`/proc/meminfo`、`/proc/version`、`/proc/uptime`、`/proc/loadavg`、`/proc/stat`、`/proc/cmdline`、`/proc/bootconfig`，并支持实际能力列表中的 ext4、F2FS、tmpfs、EROFS 普通来源。普通来源须使用标准文件操作表，暂不支持加密、fs-verity、DAX、FUSE、叠加或网络文件系统来源；必要符号、stat 路由或文件系统生命周期监控缺失时不开放普通来源。当前模式仅在 Linux 6.12 及更新内核启用；6.6 内核暂不开放，已有配置保留原模式并明确拒绝应用，不自动转换为路径重定向。模块在应用规则时预读目标普通文件；应用仍须以自身身份完整打开来源，读取时保留来源的文件身份与 SELinux 检查，无须直接访问目标。写入、创建、截断、mmap、splice 等未支持操作会拒绝，未接入的打开入口也不会悄悄提供原内容。

普通内容来源在原生及 compat 的 stat/fstat/statx 同步系统调用中默认按 B 的长度呈现 size，已打开 FD 使用自身绑定的旧内容长度，路径查询使用当前规则；明确配置的 kstat SIZE 继续优先。其余属性保留 A，proc 节点的 size 保留原值。没有全局修改 A 的 inode。普通规则持有来源 inode 防止删除后编号复用，并通过现有 superblock 生命周期回调清理。并发关闭并以同一 inode 重用同一 FD、并发修改 stat 路径字符串，以及 io_uring 元数据查询不属于这一系统调用尾部改写的精确一致性保证。

此模式每份内容最多 1 MiB，总内存最多 8 MiB（含分配开销及仍被旧 FD 引用的内容）。请先完成目标保存再重新应用；新打开的来源使用新内容，已有 FD 保留旧内容直到关闭，规则启用前已打开的 FD 不追溯替换。只读内容 FD 存活期间会正常阻止模块卸载。目标的最终路径组件不支持符号链接；支持 ext4、F2FS、tmpfs、EROFS、FUSE 上的普通文件，FUSE I/O 仍可能等待其服务响应。旧配置继续采用路径重定向，新模式使用 schema 11 和专用添加命令，旧内核会明确拒绝，不会降级为不同权限语义。

## 管理与构建

管理服务源码在 `management/`，使用独立模块内的 `cJSON` 实现，普通配置保存到 SDK 提供的模块私有目录中的单份 `config.json`。独立模块入口和 Android 构建在 `module/`，WebUI 和完整文件管理资源也随模块打包。主机验证：

```sh
python3 management/tests/simple_service_runner.py --evidence <output>
python3 tools/tests/sequential_test_runner.py <output>
```

内核可用固定 DDK 缓存构建：

```text
python3 tools/build-local-lkm.py --output build/plus-lkm-sequential/kernel-new
```

设备测试只允许核实身份的自编 Probe 和 Maple 检测。FD 计数问题按用户指示暂缓；`STATX_MNT_ID_UNIQUE` 等未由 upstream 声明的行为不额外阻止。

规则页逐条显示所属作用组，可按规则类型筛选并叠加路径或名称搜索。文件页保存并应用规则后会重新查询当前双栏已有条目的规则角标，不切换路径、不重载目录，也不清除选择或滚动位置；旧查询结果在应用边界失效。高级页最上方依次为配置导入导出与“不保留后台”。

首次没有配置文件时，模块写入内置默认配置并通过原启动流程自动应用：默认作用组隐藏 /mnt/vendor/persist/data 与 /mnt/vendor/nvdata 的内容，“仅root”作用组隐藏 /data/adb 的内容，保留三个目录本身，AVC 伪装和日志关闭，不保留后台开启。作用域参数按提供的默认配置保留，不按作用组名称推断含义。默认规则均可修改或删除，非固定作用组可删除；保存后的空配置不会在重启时补回，升级不会覆盖已有配置。应用清单尚未就绪时延后应用并自动重试，无需先打开 WebUI。

## 配置文件与 WebUI 后台

高级页提供“配置导入与导出”，使用模块内置文件管理器选择 JSON 文件或导出目录。导入只校验并生成预览，确认后载入草稿，最后由“保存并应用”提交。导出来自已保存配置，采用稳定格式标识与版本，包含全部高级配置及“不保留后台”开关，不携带会话或诊断信息；通过临时文件与不覆盖发布保存。跨设备仍须准备目标文件并校对路径、包名和内核能力。当前配置文件上限为 512 KiB。

新安装默认开启高级页“不保留后台”，已有配置沿用保存值；修改并保存后立即用于当前会话。开启时，页面首次加载后需连续在前台稳定 3 秒才启用失焦/切后台退出，启动过渡中的失焦或隐藏会重新计时，避免浏览器开屏覆盖时误退。保护结束后，页面失焦、临时切后台均立即发出退出请求；真正关页或导航在保护期内也退出。内部文件选择仍留在当前页面，不触发退出。服务停止接收新操作、收尾请求并关闭文件代理和管理服务；已应用的内核规则继续存在。原页面进入已关闭状态，需从 SKP 管理器重新打开。正常退出依靠即时通知，偶发心跳失败会重试，不因单次网络错误直接退出。宿主丢失退出事件时由约 20 秒无心跳超时回收兜底；该时间不代表强制中断内核中的操作。管理服务在启动恢复完成且空闲后同样自动退出，开机规则恢复不会依赖用户先打开 WebUI。

后台开关保存在同一 config.json 的 schema 13 webui.no_background 字段；随配置完整导入导出。导入会替换该开关草稿，保存并应用后才生效；不含该字段的旧配置采用默认关闭。旧版配置继续读取，导出文件可使用当前版本导入。

0.3.9 修复 FUSE 等后置过滤路径的内容隐藏空目录结果：当匹配“仅隐藏文件夹内容”且整批没有可见项时，清零原始结果并返回 EOF，不再生成可能被文件管理器解析为目录自身的空名称占位项。清零失败返回 EFAULT；普通选择性隐藏仍保留最小占位以继续枚举后续可见项，原 getdents/SKP 链保持。覆盖 native、compat、点目录、后续批次和缓冲区故障的主机回归；主机验证不等于 Android FUSE 实机验证。更新安装包后需重启加载新 LKM。

0.3.10 补全普通路径隐藏的空目录修复：仅隐藏子目录 ab 时，删除同级最后一个可见文件后，旧版会返回空名称记录并可能显示父目录自身。所有后过滤的全隐藏批次现在均清零并内部续读，直到找到可见条目或原系统调用返回真正的 EOF/错误，不再产生占位项。每批保留原始参数、重新获取目录 FD 并经过原 SKP 调用链；长列表可调度、可被信号中断。主机回归覆盖删除前后、下一批可见项、native/compat、FD 替换、原始参数和缓冲区错误；未宣称 Android FUSE 实机效果已验证。

0.3.11 接纳启用影子调用栈且未启用内核 BTI 时的标准 SCS 函数入口，同时覆盖编译器直接生成和加载时由 PAC 转换的形式，不限定内核小版本。目录过滤继续保留原系统调用及现有钩子；目录组合资格不足时使用后过滤。0.3.10 的全隐藏批次清零和继续读取行为保持。
